# Platform hardening contracts

## Capability declarations

`release/capability-contract.yaml` is the repository-side contract. It stays outside portable `SKILL.md` frontmatter. Package and release manifests carry a per-component assessment in addition to the packaged runtime-tool inventory.

`UNASSESSED` means the permissions and side effects have not been reviewed. It does not mean the component needs no permissions, is safe, or is available in a runtime. Runtime tools describe what the package contains; host connector availability and approval state remain runtime-dependent. The generated site catalog exposes the same review state and derives workflow details from `workflows/runtime-registry.yaml`.

## Security scan

`scripts/security/scan_skills.py` is an offline, static-only scanner. It reviews text/code sources under `skills/`, `runtime/`, `scripts/`, `workflows/`, `templates/`, and `.github/workflows/`; excludes tests, eval fixtures and build/cache directories; and does not execute inspected content. Symlinks are reported and not followed. Bidirectional controls and unexpected mid-file BOMs create a medium-severity review finding. This does not detect prompt injection comprehensively; hostile content must still be handled as untrusted input and tested behaviorally.

## Routing collision report

`scripts/eval/routing_collision_report.py` ranks the expected route against all catalog skills and workflows, and reports lexical neighbors. Its output is labelled `STATIC_SIGNAL_ONLY`, has no runtime outcome, and is published as evaluator-side CI evidence. It is an early warning for human/model-based review, not a routing pass/fail or a substitute for runtime evidence.

## Release evidence limits

All assessment states and reports remain attached to the exact source/package identity generated by the existing build process. These additions do not change skill maturity, grant host permissions, or authorize publication.
