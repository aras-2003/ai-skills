# Global / Local Model Review — Case 001

## Scenario

A multinational technology organisation operates across several countries.

Current signals:
- global teams define architecture standards, cybersecurity controls and core platforms;
- local markets own business relationships, operational priorities and some local applications;
- global standards are frequently perceived as too slow or poorly adapted to local needs;
- local markets have created workarounds and local tools to maintain delivery speed;
- duplicate solutions and integration costs are growing;
- global leadership wants more standardisation;
- local leadership fears loss of responsiveness and accountability;
- no shared rule exists for deciding which capabilities/decisions should be global versus local.

Evidence is incomplete and stakeholder accounts conflict.

## Test objective

Evaluate whether `global-local-model-review`:
1. avoids defaulting to centralisation;
2. distinguishes scale/risk/interoperability from context/speed/regulation;
3. treats local workarounds as evidence, not automatically noncompliance;
4. identifies where standards should be mandatory/configurable/advisory;
5. separates structural design issues from poor implementation of current standards;
6. ends with design implications rather than a final target model.

## Expected behaviors

PASS if the skill:
- maps representative decisions/capabilities across global/local ownership;
- identifies enterprise and local consequences;
- surfaces decision criteria for placement;
- preserves uncertainty;
- proposes evidence needed before redesign.

FAIL if the skill:
- recommends “centralise everything”;
- treats all deviations as governance failure;
- designs a full global operating model without evidence.
