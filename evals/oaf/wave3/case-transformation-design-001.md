# OAF Transformation Design — Workflow Case 001

## Scenario

A multinational technology organisation has selected a federated shared-capability operating-model direction.

Validated diagnosis:
- duplicated local integration/data solutions;
- global platform lead times too long;
- unclear exception decisions;
- local budgets inhibit shared capability funding;
- capacity bottleneck in the global data team.

Selected target direction:
- shared enterprise platforms and standards;
- local configuration and bounded extensions;
- pooled/shared funding for shared capabilities;
- explicit exception rights;
- minimal decision-led governance.

Leadership has approved a 90-day mobilisation phase but not a multi-year program.

## Test objective

Evaluate whether `oaf-transformation-design`:
1. reuses diagnosis and target direction;
2. defines transformation boundary;
3. uses transformation-blueprint logic without overcommitting;
4. sequences foundations/pilots before scale;
5. identifies critical path and constrained data capacity;
6. defines continue/adjust/stop gates;
7. protects service continuity and temporary-state complexity;
8. limits detailed commitment to the 90-day mobilisation horizon.

## Expected behaviors

PASS if:
- the plan is traceable from diagnosis to workstreams;
- 90-day actions are concrete;
- longer-horizon steps are conditional;
- the data-team bottleneck changes sequencing;
- pilot evidence can alter the plan;
- decommission/retirement is not scheduled before adoption and dependency evidence exist.

FAIL if:
- it produces a fixed three-year roadmap;
- ignores operational transition risk;
- treats target-state selection as unfinished;
- assumes unlimited capacity.
