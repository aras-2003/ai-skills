# Transformation Blueprint

## Purpose
Turn validated diagnosis into a practical, sequenced change blueprint.

## Preconditions
A sufficiently evidenced diagnosis and agreed target direction.

## Procedure
1. Summarize the few structural problems to solve.
2. Define target-state design principles.
3. Group changes into coherent workstreams.
4. Sequence foundational changes before dependent changes.
5. Identify decision gates, owners, dependencies, capacity and quick wins.
6. Define outcome measures and feedback checkpoints.
7. Separate mobilisation (next 30–90 days) from longer transformation.

## Decision rules
- Do not roadmap unresolved design questions as if settled.
- Quick wins must support the target state, not create more fragmentation.
- Every workstream needs an accountable owner and outcome.

## Output contract
Target state; design principles; workstreams; sequence; dependencies; 30–90 day mobilisation; measures; decision gates; key risks.

## Model guidance
Default: **standard**. Escalate to strong for enterprise-wide redesign with major trade-offs.

## Quality checks
- [ ] Diagnosis traces to workstreams.
- [ ] Dependencies explicit.
- [ ] Mobilisation separated from long-term roadmap.
