# Organizational Interface Review

## Purpose
Diagnose where cross-boundary interfaces fail and why.

## Procedure
1. Select only interfaces material to the target outcome.
2. Define the input, output, owner, receiver, decision rights, service expectation and escalation path.
3. Trace one or more real cases through the interface.
4. Identify wait states, duplicate approvals, missing information, ownership gaps and resource conflicts.
5. Distinguish interface failure from deeper structural or decision-rights failure.
6. Recommend the smallest validation or interface change.

## Decision rules
- Do not add a forum simply because an interface is weak.
- Handoffs should have observable inputs/outputs and named owners.
- A coordination symptom may indicate a decision-rights or resource problem upstream.

## Output contract
Interface | input | output | owner | receiver | decision dependency | observed friction | consequence | evidence needed | smallest change.

## Model guidance
Default: **standard**.

## Quality checks
- [ ] Real interfaces, not abstract boxes.
- [ ] Handoffs linked to consequences.
- [ ] Root cause distinguished from coordination symptom.
