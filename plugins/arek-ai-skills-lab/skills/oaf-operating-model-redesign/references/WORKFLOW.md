# OAF Operating Model Redesign Workflow

## Purpose
Move from an evidenced operating-model diagnosis to a bounded redesign without jumping directly from symptoms to an org chart.

## Preconditions
Require:
- validated operating-model misfits;
- representative interface/decision evidence;
- explicit business outcomes and constraints.

## Stages
1. **Confirm diagnosis** — run or reuse `operating-model-review`; if global/local tension is material, add `global-local-model-review`; if interface failures dominate, add `organizational-interface-review`.
2. **Resolve decision architecture** — use `decision-rights-review`; use `decision-bottleneck-analysis` where latency is a material symptom.
3. **Define design principles** — state which outcomes require enterprise consistency and which require local autonomy.
4. **Generate bounded options** — compare 2–3 operating-model options; do not optimize only for hierarchy.
5. **Test options** — authority/accountability/resources, interfaces, funding/capacity, architecture, decision latency, transition risk.
6. **Design governance only after option choice** — use `governance-design` for the chosen decision model.
7. **Sequence change** — use `transformation-blueprint` only after the target direction is sufficiently decided.

## Output contract
Diagnosis recap; design principles; options; trade-offs; critical decisions; selected direction or unresolved choice; validation/pilot plan; next workflow/skill.

## Stop conditions
Stop before design if evidence does not distinguish structural failure from poor execution of the current model.
